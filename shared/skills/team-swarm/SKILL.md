# Team swarm

Inspect project instructions and the actual controller/runtime before dispatch.
Use one integration owner, a pinned baseline, disjoint writer paths, explicit
checks and a stop condition. Preserve primary dirty work. A worktree is not a
security boundary. Read-only review should receive the relevant diff and test
evidence; validate findings independently.

For this machine's controller, read
~/.codex/skills/team-orchestrator/SKILL.md and only the references relevant to the
chosen lane. Its v0.1 authenticated model dispatch remains blocked pending
provider-only egress, isolated authentication and exact-runtime canaries. Do not
invoke legacy scripts/swarm or cc-lxc model commands to bypass that gate.
Network-free fixture qualification does not qualify a model worker.

Native OpenCode has separate local scout/reviewer profiles. They are cooperative
read-only agents on the operator's machine, with their own permissions and fresh
contexts. Use them only for the bounded question; they are not isolated Proxmox
workers. Do not silently change provider or spend. See
[native setup](https://irregularpedia.org/ai-ml/opencode/) and use the installed
vibe-orchestrator and agent-reliability skills when routing or measuring workers.

Before integration, inspect the exact returned diff and run appropriate checks
from the combined tree. A completion message or judge endorsement is not
acceptance. Publication follows the user's authorization and repository policy.
